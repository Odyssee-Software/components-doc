# API Report

This directory contains the API surface report for Pulse Framework, generated by [@microsoft/api-extractor](https://api-extractor.com/).

## What is an API Report?

The API report (`pulse-framework.api.md`) is a human-readable summary of the **public API surface** of the package. It includes:

- All exported functions, classes, interfaces, and types
- Function signatures with parameter types and return types
- JSDoc comments and documentation
- Type definitions and their structure

## Purpose

The API report serves several important purposes:

1. **Track API Changes** — Git diffs of this file clearly show what changed in the public API
2. **Prevent Accidental Breaking Changes** — CI/CD can fail if the API surface changes unexpectedly
3. **Documentation** — Provides a quick reference of the entire API in a single file
4. **Code Review** — Makes it easy to review API changes during pull requests

## How It Works

When you run `npm run build:api`, API Extractor:

1. Analyzes the TypeScript declaration files in `dist/`
2. Extracts all public APIs (anything exported from the main entry point)
3. Generates `pulse-framework.api.md` with the complete API surface

## Workflow

### When Adding New APIs

```bash
# 1. Add your new public API to the code
# 2. Build and extract API
npm run build:api

# 3. Review the changes to pulse-framework.api.md
git diff docs/api-report/pulse-framework.api.md

# 4. If the changes are intentional, commit them
git add docs/api-report/pulse-framework.api.md
git commit -m "feat: add new API for XYZ"
```

### When the API Report Changes Unexpectedly

If API Extractor detects changes that you didn't intend:

1. Review the diff in `pulse-framework.api.md`
2. Determine if the change is:
   - **Intentional** → Commit the updated report
   - **Accidental** → Fix your code to restore the original API
   - **Breaking** → Consider versioning and migration strategy

## Versioning Guidelines

Use semantic versioning based on API changes:

- **Patch (0.1.0 → 0.1.1)** — Bug fixes, no API changes
- **Minor (0.1.0 → 0.2.0)** — New APIs added, backward compatible
- **Major (0.1.0 → 1.0.0)** — Breaking changes to existing APIs

## Example API Report Entry

```typescript
// @public
export function signal<T>(initialValue: T): Signal<T>;

// @public
export interface Signal<T> {
    (): T;
    (newValue: T): void;
    subscribe(callback: (value: T) => void): Unsubscribe;
    value: T;
}
```

## CI/CD Integration

In CI/CD pipelines, you can enforce API stability:

```bash
# Fail build if API report is out of sync
npm run build:api
git diff --exit-code docs/api-report/
```

This ensures developers regenerate the API report when making API changes.
